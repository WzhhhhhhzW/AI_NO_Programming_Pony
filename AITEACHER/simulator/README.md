# 小马 3D 教学仿真

## 使用（V16.9）

1. 点击顶部或左侧 **3D 仿真**，自动载入当前工程；未打开工程时使用内置 Dog 实例。无需开始、播放或填写时间指令。
2. 右侧 **蓝牙遥控** 点击站立、趴下、前进、左转、右转、摇尾巴、握手或哈气。发送原工程的 ASCII 字符 0–7，实际执行 UART 回调与动作代码。
3. 程序持续运行，保留变量和外设状态。当前动作未结束时保留最后一次按钮指令，待源码重新调用 UART Read 后发送。工程未开启串口接收时，指令不会绕过源码强制执行。
4. 使用顶部 **打开工程** 选择已有工程。保存后自动重新载入；再次打开仿真也会读取未保存编辑。遥控按钮按当前 MODE[0] 动作分支和蓝牙回调生成，新增后退分支后会显示对应按钮。手动点击“重新载入代码”相当于虚拟重新上电。
5. 点击 **角度测算** 暂停代码与物理，用五路滑块手动摆姿。显示目标角度、最近的整数参数、整数可达角度、脉宽和可复制的 `*_SetDuty(...)` 代码。退出后恢复原会话。
6. **舵机角度校准** 可逐路设置零位、方向、°/ms，并在本机保存。整数到脉宽对应表由当前工程自己的 SetDuty 函数执行获得；当前 Dog 右前腿 −36° 对应 9。界面显示所选整数对应的可达角度。
7. **物理环境** 可调整质量、重心、摩擦和最大力矩；“应用参数 / 扶正回原点”重置物理位置，不重启 C 程序。若动作造成侧翻，界面如实显示。
8. 仿真练习仅包含应用源码与生成配置；真实编译、烧录仍需完整 e2 studio/FSP 工程。

## 模型来源与校准

模型来自用户提供的 `建模源码.zip` 中的 `小马打印.3mf`，共八个零件，使用原文件保留的 assemble 变换和毫米尺寸。显示网格按 0.25 mm 顶点聚类简化。四条腿的转轴来自网格安装孔中心；尾巴卡口轴位置与方向目前按装配位置近似，需要实机校准。

默认站立零位使用 Dog 中 7% × 20 ms = 1.4 ms，角度比例暂设 90°/ms，速度上限校准为 180°/s。右侧可逐路修改舵机零位、方向及角度比例。这些机械参数尚未通过实机测量，不能据此保证绝对角度准确。

## 执行范围

`engine.py` 使用 pycparser 解析并有界解释执行应用 C 源码，执行循环、分支、函数、变量、数组及常见整数运算。没有按“前进”“握手”等名字播放预设动作：模型只消费实际 GPT 输出和延时事件。

已实现：Dog 的主晶振→PLL→PCLKD 时钟配置、GPT Open/Start/Stop/InfoGet/DutyCycleSet/PeriodSet、单字节 SCI UART Read/回调、IIC OLED 命令与帧缓冲输出。OLED 字模和位图来自原工程；不需要外部 AI 接口。

批量诊断保留 60 秒时长上限；实时模式持续执行，按延时等待真实时间并接收按钮指令，限制每段计算的解释步数和计算时间，近期事件采用有界存储。遇到不支持的语法、函数或外设时明确报错。它不是完整 ARM 指令集、编译器或全部 FSP 的仿真器，不支持任意指针算术、RTOS、DMA、中断优先级、电路与总线电气时序。仍需使用真实编译器检查最终固件。

### 刚体物理

使用离线 cannon-es 0.20.0：重力 9.81 m/s²、机身与五个活动零件的刚体、五个铰链、默认限速 180°/s 且限力矩的电机、地面碰撞和摩擦。机身位置与姿态完全来自物理解算，不按动作名称施加转向或位移。

碰撞体由原零件网格沿高度分段近似；机身和头部采用盒状近似。初始估计参数：机身 0.45 kg、单腿 0.025 kg、尾巴 0.018 kg、地面摩擦 0.25、舵机最大力矩 0.18 N·m。质量、惯量、重心、足底摩擦和尾轴均未实测。尚未模拟零件之间的自碰撞、壳体变形、供电、电流、温升或焊接。

V16.2 根据用户提供的“标准工程实机左右转不侧翻”表现校准：重心从模型坐标 +8 mm 降至 −15 mm，地面摩擦从 0.65 改为 0.25，舵机速度上限从 360°/s 改为 180°/s。真实 C 输出的连续六次左转、右转、交替转向均通过 30/60 FPS 和 20% 动作时序拉长测试；保留重力、接触和转向，没有锁定机身姿态或自动扶正。这属于行为校准，参数并非实测值，修改动作后仍可能失稳。右侧“恢复标准工程参数”可重置这些默认值。

cannon-es 来源为 npm 官方发布的 0.20.0 包，校验 SHA512 后将浏览器 ESM 导出封装为本地脚本；许可证在 assets/CANNON-LICENSE.txt。参考：https://pmndrs.github.io/cannon-es/docs/ 。

## 原工程诊断

原始 Dog 代码初始化定时器时配置 50% 占空比（20 ms 周期时为 10 ms），该输入超出舵机校准范围；四肢对应关节不提供驱动力，仍受重力和接触影响。V16.3 尾巴按已安装的保持型舵机建模：上电保持装配零位，有效指令更新目标角度，无新输出或超范围输入时继续保持上一目标。仍通过有限力矩的关节电机抵抗重力，摇尾指令正常驱动；V16.4 已移除侧栏代码诊断面板及提示计数。原 OLED_ShowPicture 的部分 70 像素高度绘制会访问 64 像素帧缓冲之外，仿真仍隔离越界访问。原文件保持不变，学生可在练习副本中修正并比较效果。

## 开发验证

`python -m unittest discover -s tests -p "test_simulation*.py" -v`

`node tools/check_physics.cjs` 验证重力、站立、转向位移及摩擦敏感性。

`node tools/check_turn_stability.cjs` 从标准 C 源码生成连续转向轨迹，复现旧默认值侧翻，再验证新默认值在不同帧率和动作时序下不侧翻；报告输出到 build/turn_stability_report.json。

`tools/check_simulation_ui.py` 使用隔离配置运行窗口与网页验证；设置 `SIM_TEST_PLATFORM=windows` 可验证真实图形后端。Three.js r160 与许可证位于 assets，发行包离线加载所有资源。
